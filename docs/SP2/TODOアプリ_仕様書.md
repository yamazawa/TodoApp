[SP2]TODOアプリ仕様書

前提 : `docs/archive/SP1/TODOアプリ_仕様書.md`(SP1仕様)からの変更点を記載する。
記載のない項目はSP1仕様を維持する。

# A. モデル設計の変更点

## TodoItemの保持項目

- 本文(Body)を削除する
- タイトルのnull許容をやめる(必須入力にする)
  → フォーカスアウト時に未入力なら直前の値に戻す
- メモ情報リストは最低1件を保持する
  → 0件になる操作はModel上のルールとしてブロックする
  → メモ情報の削除、TODOへの変換は、メモ情報が
    2件以上のときのみ実行可能にする
- 新規TODO追加時、メモ情報リストに
  タイトル「README」のメモを1件追加する

## メモ情報の保持項目

- タイトルのnull許容をやめる(必須入力にする)
  → フォーカスアウト時に未入力なら直前の値に戻す
- 本文は変更なし

## 不要になるロジックの削除

- タイトルのnull許容に伴うUI・変換処理
  (フォーカス時のプレースホルダ表示、EmptyStringToNullConverter等)
  は不要になるため削除する

# B. 画面設計の変更点

## 上下レイアウトの廃止

- 上半分(タイトル/ステータス/本文の表示領域)を削除する
- 上半分と下半分を分けるドラッグ境界を削除する
- パンくずリストはウィンドウ最上部に1行のバーとして残す
  → 詳細は「パンくずリストの拡張」を参照
- タイトル/ステータスは下半分の左側のリストで表示する
  → リスト項目のタイトル表示はSP1仕様を継続する
  → ステータス表示は「リスト項目のステータス表示変更」を参照
- ステータス変更は子TODOリストの右クリックメニューから行う
  → ステータスが未対応の場合「対応中に変更」を表示
  → ステータスが対応中の場合「完了に変更」を表示
- TodoDetailEditorはメモ情報表示専用になるため、
  ステータス関連(コンボボックス・背景トリガー)を削除する
- TodoDetailEditorのタイトル欄も削除する(本文のみにする)
  → タイトルはパンくずリストに表示するため重複させない
  → タイトルの変更はリスト側の右クリック「編集」で行う

## リスト表示の簡略化

子TODO・メモ情報の件数状況に応じて、以下3パターンで
リスト表示を切り替える。

### 状況① 子TODOが0件、メモ情報が1件

- リスト表示はせず、そのメモ情報の本文のみを表示する
  → タイトルはパンくずリストに表示するため、重複させない
- 下部に「TODOリストを追加」「メモ情報をリスト化」を表示する
  → 「メモ情報をリスト化」: メモ情報を追加し状況②に遷移する
  → 「TODOリストを追加」: TODOを追加し状況③に遷移する
  → 追加された項目のテキストボックスにフォーカスする

### 状況② 子TODOが0件、メモ情報が2件以上

- 左側にメモ情報リストを表示し、右側に選択中メモ情報を
  状況①同様に表示する
- 「メモ情報をリスト化」ボタンは非表示にする

### 状況③ 子TODOが1件以上

- 左側にタブ表示(TODOリスト/NOTEリスト)をする
  → タブ名は「子TODO」→「TODOリスト」、
    「メモ情報」→「NOTEリスト」に変更する
  → 初期選択タブは「NOTEリスト」にする
- NOTEリスト選択時 : 選択中メモ情報を状況①②同様に表示する
  → 下部の追加ボタンは非表示にする
- TODOリスト選択時 : 選択中TODOを本レイアウトに従い
  再帰的に表示する
  → 孫項目で表示を止めず、末端まで再帰的に表示を繰り返す
    (SP1からの変更点)
  → 自己参照可能な1つのUserControlとして実装し、
    右側に選択中TODOを同じUserControlで埋め込む
  → MainWindow.xamlは、パンくずリストと
    ルートTODOのUserControl配置のみに簡素化する

## パンくずリストの拡張

現状のパンくずリストは、祖先(ファイルシステム上/インメモリ)を
並べるのみ。以下2点を右側に追加する。

- 祖先の右に、現在ウィンドウ全体で表示中のTODOタイトルを
  追加する
  → リンクにはしない(既にその表示位置のため)
- さらにその右に、再帰的に表示中のTODO項目を
  一通り並べる
  → 各項目はリンクにし、選択するとそのTODOを
    新たな表示位置(ルート)としてジャンプする
  → 再帰的に表示中のTODO項目は、TodoItemの
    SelectedChildTodo/SelectedTabIndexを辿って算出する
    (画面のView構造には依存させない)
- 末端でメモ情報を表示している場合、その右に
  表示中のメモ情報のタイトルを追加する
  → リンクにはしない

## リスト項目のステータス表示変更

背景色でのステータス表示は、選択中の項目が分かりづらいため
廃止する。

- 子TODOリストの項目背景をステータスで変える表示を廃止する
- TODO項目の左側に、ステータスに応じたアイコンを表示する
  → `image/未対応.ico`
  → `image/対応中.ico`
  → `image/完了.ico`
- アイコンをダブルクリックするとステータスを進める
  → 右クリックメニューの「〇〇に変更」と同じ動作
  → 完了の場合はダブルクリックしても変化しない

## NOTE一覧の表示方法変更

NOTE一覧はリスト表示ではなく、NOTE本文の上に並べるタブ表示に変更する。

### TODOが0件、NOTEが1件

状況①のまま変更しない。

### TODOが0件、NOTEが2件以上

- NOTE本文の上にNOTE一覧タブを表示する
  → 左右分割・独立したリスト表示は廃止する

### TODOが1件以上

- リスト上部のTODO/NOTEタブ切り替えは廃止する
- リストには以下を順に表示する
  → A. 先頭に選択中NOTEのタイトルを1件表示する
  → B. Aの後にTODOリストを表示する
- Aを選択した場合、右側に「TODOが0件、NOTEが2件以上」と
  同じNOTE一覧タブ+本文を表示する
- Bの項目を選択した場合は従来通り、選択中TODOを
  再帰的に表示する

## タイトル編集の確定タイミング

- TODO/NOTEのタイトル編集は、入力途中では反映せず
  フォーカスアウト時に確定する
  → 未入力のまま確定した場合は直前の値に戻す
- コントロール以外の場所をクリックした場合も
  フォーカスを外して確定する

## 右クリックメニューへの「開く」追加

- TODO項目 : 「開く」を押すとフォルダをエクスプローラーで開く
- メモ情報 : 「開く」を押すとmdファイルを選択状態で
  エクスプローラーで開く

# C. ファイル設計の変更点

## TODO情報のREADME(0_README.md)の廃止

- 従来TODO本文を保持していた0_README.mdの固定ファイルは
  廃止する
- 新規追加TODOの初期メモ「README」は、メモ情報の命名規則
  ([連番]_[タイトル].md)に従う通常のファイルとして保存する
- パンくずリストの祖先判定条件(SP1仕様②)は、0_README.mdの
  存在確認から_save.jsonの存在確認に変更する

## 起動時TODOフォルダパスの設定方法

- 現在は定数定義しているファイルパスをiniファイルで
  指定可能にする
- iniファイルは`%AppData%\TodoApp\`に配置する
  (settings.jsonと同じフォルダ)
- Debug実行時は`%AppData%\TodoApp_Debug\`に分ける
  (開発中の動作確認が本番データに影響しないようにするため)
